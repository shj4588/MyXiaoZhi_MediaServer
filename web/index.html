AlphaPi（小智）设备同一个地址，按客户端自动转码
—
小智固件没有 mp3 解码器（flac/aac 更不行），音频通路只认 8bit / 24000Hz / 单声道。 所以凡是被认成小智的请求，服务端都会现用 ffmpeg 解码重采样，包 44 字节 WAV 头（长度字段 0xFFFFFFFF）推流； R1 那条路一个字节都不变。
识别方式三选一：① 直接用 /ap/ 前缀（最稳，固件不发 UA 也不会认错） ② URL 带 ?dev=ap ③ UA 里带 alphapi / xiaozhi / esp32 / espressif。
电台默认不转码，地址原样给 MP3（需要 WAV 时加 ?fmt=wav）。

📖 书级续播 同一组设备共享一份进度（v1.7.38 按组隔离），组内换设备说「继续听」接着放
设备靠固件上报的 WiFi MAC 区分（X-Dev-Mac 头）；老固件没报就退回按来源 IP，换 IP 会被当成新设备。
有声书续播（v1.7.13 起为书级共享）：任一台设备说「听三体 / 继续听」→ 接着最近有人在听的那集，从停下位置往前 10 秒开始。 歌曲和电台不续播（歌单是连播流，电台本来就没有"进度"）。
进度是按服务端实际推出去的音频字节数结算的，比耳朵听到的略超前，所以续播统一回退 10 秒。
设备分组 同组共享播放进度（有声书 / 音乐 / 电台），不同组互不可见 刷新
新出现的设备默认是「独立组」，进度只属于它自己。把几台设备放进同一个组，它们就能互相接着听。 移动设备后，它只认新组里的进度记录（旧组的记录仍保留在原组，不会删）。
